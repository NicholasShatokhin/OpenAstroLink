OAL CORE DEVELOPMENT

Ownership, operations та evidence мають бути явними.

Entry point для contributors node, core, GUI, protocol, algorithms і build system.

Read order

CURRENT_STATUS → CURRENT_CHECKLIST → ARCHITECTURE → OAL_SPECIFICATION → OAL_API → VALIDATION. Перед mount transforms читати MOUNT_GEOMETRY.

Core invariants

  • Node володіє device sessions.
  • Native drivers default; INDI optional.
  • Mount v9 geometry frozen після HIL.
  • Main/guide resource locks independent.
  • Science recording upstream від preview/network work.
  • EN docs canonical, UA mirrors synchronized.

Feature workflow

Визначити ownership/resources, query vs operation, capabilities, device-specific boundary, cancel/failure semantics, regression coverage, docs sync і реальний qualification level.

Driver/protocol work

Використовуйте include/oal/driver_api.h, manifest schema, NATIVE_DRIVER_SDK.md, OpenAPI та OAL specification. GUI не повинен бути shadow source protocol state.
