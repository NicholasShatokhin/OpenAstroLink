WHAT IT IS · WHY IT EXISTS

OpenAstroLink separates the observatory control layer from any one GUI.

The node owns hardware sessions and operations; OpenAstroSuite and third-party applications are clients. This enables native-first hardware control, headless/remote operation, explicit cancellation/resource locks and science acquisition that does not depend on preview rendering.

What was missing from existing solutions? Not “a better INDI or ASCOM”, but a different architectural combination: node ownership + native drivers + workflow operations + independent science/preview data planes + an open protocol for other software. Existing ecosystems remain compatibility targets.

v0.2.10.58 · WEBRTC PREVIEW

WebRTC is now an optional native preview transport with OALV fallback.

The node signals on /webrtc and offers independent oalv-main and oalv-guide DataChannels. OALW v1 fragments carry the existing OALV/JPEG preview packet, while raw SER remains upstream of preview/network work.

Channels are unordered and partially reliable, with latest-frame semantics and a 2 MiB backpressure gate. /video automatically remains available per role when WebRTC is not ready.

Static regression remains green and the fresh Windows build now passes. Canon/ZWO EAF runtime ABI retest plus WebRTC/QHY/Dual-Live HIL are pending. RTP H.264/H.265/AV1 media tracks are not part of this checkpoint yet.

OFFLINE NAVIGATION + FRAMING · v0.2.10.53

Navigate, frame the camera and preview mosaics without a full planetarium.

The left workspace includes an offline horizon map for catalogue or free-point GOTO. After plate solve it draws the measured rotated camera rectangle from the solved center, scale, image size and position angle. Before solve it can show independent predicted main- and guide-camera footprints from the optical profile. The Scheduler mosaic columns, rows, overlap and rotation can be previewed as a tile grid around the selected target.

When Stellarium's optional Remote Control plugin is enabled, OpenAstroSuite can export the solved, main, guide or mosaic-envelope frame to Stellarium's built-in rectangular FOV marker. Standard Telescope Control remains the mount position/GOTO bridge.

Catalogue-object → Scheduler transfer is already confirmed in the running GUI. All mount actions still use the active OpenAstroLink backend and the HIL-qualified direct-MC v9 geometry is not duplicated or changed.

NATIVE FIRST

Keep hardware ownership close to the hardware.

openastrolink-node owns device sessions and long-running operations. Local or remote GUIs use HTTP/WebSocket; Stellarium uses the telescope bridge. Native OAL drivers are enabled by default. INDI is opt-in for compatibility or hardware that does not yet have a native driver.

Road to OAL 1.0

Unattended-observatory hardening remains separate from the supervised Beta: durable mid-block checkpoints, production guiding, meridian-flip recovery, weather/roof/power safety, TLS/auth/roles/audit, reliable event replay, driver isolation, durable science provenance and Smart Telescope UX.
